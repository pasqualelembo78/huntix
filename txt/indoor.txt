CONTEXT GENERALE
================

Obiettivo: Arricchire il gioco indoor AR "Nascondi e Cerca" di Huntix con un
sistema di "Room Scan + Interazione Mobili" che permette all'utente di:

1. Scansionare la stanza una volta sola (Modalità Interattiva)
2. Marcare i mobili come POI interattivi (tocca → si apre un cassetto, si accende una TV)
3. Salvare la stanza (locale + backup Firebase)
4. Riconoscere la stanza alla riapertura (pose matching ARCore anchors)
5. Giocare: uova nascoste vicino ai POI, POI come fonti di indizi

Tecnologie in uso:
- Android: SceneView 2.2.1 + ARCore (NON AR Foundation)
- Unity: Progetto separato in /unity-project/ per asset 3D
- Backend: Firebase Firestore + Realtime Database (esistente)
- Persistenza: SharedPreferences (esistente) + Firebase backup (da aggiungere)

data class InteractivePOI(
    val poiId: String,              // UUID del POI
    val anchorId: String,            // ARCore anchor ID locale
    val label: String,             // "wall_shelf", "tv_stand", "sofa_left", "desk_top"
    val customName: String,        // nome dato dall'utente
    val worldPose: FloatArray,     // 7 float: tx, ty, tz, qx, qy, qz, qw
    val planeIndex: Int = -1,      // indice del piano ARCore
    val interaction: String,       // "open_drawer", "toggle_tv", "spin", "pull_out"
    val metadata: Map<String, String> = emptyMap(),
    val isFound: Boolean = false,  // se l'indizio del POI è stato scoperto
    val createdAt: Long = System.currentTimeMillis()
)

data class InteractiveRoom(
    val roomId: String,             // UUID stanza
    val name: String,               // nome utente
    val ownerUid: String,           // UID Firebase
    val semanticPlanes: List<RoomMapRepository.SemanticPlane>,
    val pois: List<InteractivePOI>,
    val safePos: FloatArray?,       // pose cassaforte (7 float)
    val eggMeta: List<EggMeta>,    // offset + colore + forma uova
    val createdAt: Long,
    val updatedAt: Long
)

data class EggMeta(
    val idx: Int,
    val offset: FloatArray,  // offset da safe (3 float) o assoluto (7 float)
    val colorIdx: Int,
    val shape: String,
    val isTrap: Boolean,
    val nearbyPOI: String?   // POI a cui l'uovo è associato
)

NUOVI FILE — MANAGER E LOGICA
================================================================================

1. InteractiveRoomManager.kt
   Posizione: /app/src/main/java/com/intelligame/huntix/InteractiveRoomManager.kt

   Responsabilità:
   - startInteractiveScan(): avvia modalità scansione interattiva
   - markPOIAt(hit, suggestedLabel): crea POI quando utente tocca un piano
   - spawnPOIVisual(poi, anchor, label): istanzia asset 3D per il POI
   - tryLoadRoom(session): riconosce stanza tramite pose matching
   - roomRecognitionScore(room, planes): calcola matching score (soglia 0.8)
   - loadRoom(room, session): ricostruisce tutti i POI
   - queuePOISave(poi): persiste POI (SharedPreferences + Firebase)
   - restoreSafeAndEggs(room): ripristina safe + uova

   Dipendenze:
   - RoomMapRepository (esistente) per SemanticPlane
   - LocalAnchorStore (esistente) per persistenza locale
   - SceneView ARSceneView per accesso a session/engine

2. FurnitureInteractionManager.kt
   Posizione: /app/src/main/java/com/intelligame/huntix/FurnitureInteractionManager.kt

   Responsabilità:
   - onPOITapped(poiId): gestisce tap su POI (open_drawer, toggle_tv, spin)
   - provideHintForNearbyEgg(eggIdx, poiId): POI fornisce indizi vicino uova
   - checkPOITap(event): raycast su POI interattivi in fase PLAY

   Dipendenze:
   - UnityPlayer.UnitySendMessage per trigger animazioni Unity
   - MainActivity per overlay hint suoni

3. RoomFingerprintManager.kt  [OPZIONALE — v2]
   Posizione: /app/src/main/java/com/intelligame/huntix/manager/RoomFingerprintManager.kt

   Responsabilità:

FLUSSO COMPLETO (step by step)
================================================================================

FASE 1: SESSIONE INIZIALE (modalità Interattiva)
------------------------------------------------
1. Utente: IndoorModeSelectionActivity → "✨ Inizia" (Modalità Interattiva)
2. MainActivity: riceve intent con game_mode="interactive_room"
3. MainActivity: inizializza InteractiveRoomManager.startInteractiveScan()
4. RoomScanManager: guida utente a camminare (UI "scanOverlay" personalizzato)
5. RoomScanManager: quando >= 5 piani → "Scansione completa"
6. UI cambia: mostra carosello "Seleziona tipo di mobile da marcare"
7. Utente tocca un piano → FurnitureTypeDialog (sceglie: mensole, TV, divano, etc.)
8. InteractiveRoomManager: markPOIAt() → crea anchor + spawn asset 3D + salva POI
9. Ripete per ogni mobile (parete attrezzata, TV, divano, scrivania)
10. Utente: piazza cassaforte (SETUP_SAFE) e uova (SETUP_EGGS) — flow esistente
11. InteractiveRoomManager: saveRoom() → salva POI + safe + uova su SharedPreferences + Firebase

FASE 2: SESSIONE SUCCESSIVA (ricarica stanza)
----------------------------------------------
1. Utente: IndoorModeSelectionActivity → "📂 Carica stanza"
2. RoomListDialog: mostra stanze salvate (SharedPreferences + Firestore)
3. Utente tocca una stanza → MainActivity con extras: game_mode="interactive_room", room_id="xxx"
4. InteractiveRoomManager: tryLoadRoom(session) → roomRecognitionScore() matching pose
5. Se matching > 0.8:
   a) loadRoom(): ricrea anchor ARCore per ogni POI
   b) spawnPOIVisual(): istanzia asset 3D (visibili solo in edit mode)
   c) restoreSafeAndEggs(): ricostruisce safe + uova
6. Se matching < 0.8:
   - Dialog: "Stanza non riconosciuta. Rifare scansione? Posizionare manualmente?"
   - Se "Posiziona manualmente": passa alla modalità editing

FASE 3: GIOCO (INTERACTIVE_PLAY)
---------------------------------
1. Utente: "Avvia caccia" (btnStart)
2. GamePhase → INTERACTIVE_PLAY (simile a PLAYING ma con POI)
3. ArSceneManager.checkProximity():
   - Distanza camera→uovo → mostra/nasconde uovo
   - Distanza camera→POI → mostra poiLabelOverlay ("📺 TV Stand")
4. FurnitureInteractionManager.checkPOITap():
   - Raycast su POI → TriggerInteraction() → UnitySendMessage
   - Unity: FurnitureAnimator trigger → animazione (cassetto aperto, TV accesa)
5. MainActivityHints: se POI aperto → fornisce indizio ("Cerca sotto il divano!")
6. Gioco Nascondi e Cerca avanza come oggi:
   - Trova uovo → raccogli → vai alla cassaforte
   - POI forniscono indizi bonus (se già interagiti)

NOTE TECNICHE IMPORTANTI
================================================================================

1. ARCore Persistent Anchors
   - Android non supporta nativamente persistent anchors (solo Cloud Anchors)
   - La soluzione adottata: salva pose assoluta + usa room pose matching
   - Soglia di matching: 0.5m di tolleranza per pose, 0.8 di soglia per score
   - Se matching fallisce: UI per riconoscimento manuale

2. Asset Pipeline (Unity → Android)
   - Assets 3D devono essere in unity-project/Assets/Resources/InteractivePOI/
   - UnitySendMessage richiede che gli script Unity siano compilati nell'AAR
   - Il pomeriggio: ricostruisci AAR Unity con nuovi script C#

3. Firebase Backup
   - Salva su Firestore: room_maps/{roomId} con pois[], planes[], safePos
   - Backup automatico quando utente lascia la stanza
   - Restore manuale: "Carica stanza" → RoomListDialog → carica da Firebase

4. Performance
   - POI visibili: MAX 15 POI per stanza (per performance SceneView)
   - Asset 3D: ogni POI usa un modello Kenney semplice (< 2k poligoni)
   - Pooling: riusa AnchorNode + modelNode invece di distruggere/ricostruire

5. Errori da evitare
   - NON usare Cloud Anchors per POI singoli (lenti, TTL 30 giorni)
   - NON salvare pose absolute in Coordinate ARCore (drift over time)
   - USA offset relativo + room fingerprint per matching robusto
