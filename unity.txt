HUNTIX — PIANO DI MIGRAZIONE A UNITY (STRATEGIA IBRIDA)
==========================================================

OBIETTIVO
Trasformare Huntix da gioco Android nativo a un sistema ibrido:
Android nativo per UI/menu/mini-giochi + Unity come motore di gioco
per le sezioni 3D/AR (outdoor, RealLife, indoor).

PERCHÉ LA STRATEGIA IBRIDA
- Huntix ha sezioni che NON necessitano di Unity (mini-giochi 2D,
  termoculla, squadre, profilo, impostazioni).
- Convertire TUTTO in Unity è uno spreco: più complesso, APK più
  grande, due codebase da mantenere per nulla.
- La strategia ibrida massimizza i vantaggi di Unity dove servono
  (AR, 3D, fisica, animazioni) e mantiene Android nativo dove è
  sufficiente (layout, liste, timer).

SEZIONI: DOVE VANNO
===================

→ UNITY (motore di gioco 3D/AR):
  - Outdoor AR (caccia alle uova nel mondo reale)
  - RealLife (negozi, lavoro, social, NPC)
  - Indoor 3D (caccia uova dentro casa)
  - Mini-giochi AR (se presenti in futuro)

→ ANDROID NATIVO (Kotlin):
  - Mini-giochi 2D (carte, solitario, briscola, ecc.)
  - Termoculla / schiusa uova (UI timer + barre)
  - Squadre / classifiche (liste, layout, Firebase)
  - Profilo / inventario (UI di configurazione)
  - Impostazioni (toggle, preferenze)
  - Menu principale e navigazione
  - Login / registrazione

COMUNICAZIONE ANDROID ↔ UNITY
==============================

Unity si integra come libreria AAR nel progetto Android.
L'app Android avvia Activity Unity quando serve il gameplay 3D/AR
e torna ad Android quando il giocatore è nei menu.

Bridge Android → Unity:
  UnityPlayer.UnitySendMessage("GameManager", "OnEvent", jsonData)

Bridge Unity → Android:
  AndroidJavaClass("com.intelligame.huntix.Bridge").CallStatic(...)

Dati condivisi:
  - Firebase Firestore (stesso schema in entrambi)
  - SharedPreferences (Android) → PlayerPrefs (Unity) per cache locale
  - File JSON su storage condiviso per dati offline

CONFRONNO: STRATEGIE POSSIBILI
----------------------------------------

Strategia A: Tutto in Unity
+ Un solo codice base
+ Massima coerenza grafica
- APK enorme (~80-100MB)
- Mini-giochi 2D in Unity sono contorti
- Build lente
- Troppo complesso per sezioni semplici

Strategia B: Tutto in Android nativo
+ APK leggero (~30MB)
+ Build veloci
+ Mini-giochi semplici
- Nessuna fisica, no NavMesh, no animazioni
- 3D limitatissimo, no character controller
- Non scalabile per un gioco 3D completo

Strategia C: Ibrida (SCELTA CONSIGLIATA)
+ Unity dove serve (AR, 3D, fisica, animazioni)
+ Android nativo dove basta (UI, mini-giochi, timer)
+ APK dimensione controllata (Unity on-demand)
+ Ogni sezione usa lo strumento giusto
+ Scalabile e manutenibile
- Due codebase (Kotlin + C#)
- Bridge da implementare e testare
- Build leggermente più complessa

CONCLUSIONE: La strategia ibrida è la scelta migliore per Huntix.
Unity gestisce il gameplay 3D/AR, Android gestisce l'UI e i mini-giochi.
Il risultato è un gioco professionale, performante e manutenibile.
