# Multiplayer Specification - Huntix

## Overview
Huntix is a **multiplayer** city game. Multiple players can explore the same city together, and the city generated by each client MUST be identical for all players in the same zone. The core principle is **deterministic city generation**: same OSM tile + same style = same city, everywhere.

## Core Constraints

### 1. City Generation Must Be Deterministic
- **Same inputs → Same city**: Given the same OSM tile data, player position, and `CityStyle.UseQuaternius`, every client must generate the exact same buildings, same prefabs, same layout, same heights.
- **GeoBlockSeed**: `BuildingPlacer.cs` uses absolute latitude/longitude (`b.c[0]`, `b.c[1]`) as the style block seed (NOT chunk-local coordinates). This guarantees regeneration always yields the same building prefab for the same real-world location. **Never revert to chunk-local seeds.**
- **Never use `Random`, `Time.time`, or session-dependent state** to pick prefabs, heights, or material variants in building generation. Only `GeoBlockSeed` + building hash.

### 2. No Per-Building Per-Frame Updates
- **Prohibited**: Do not add `Update()`, `LateUpdate()`, or per-building coroutines that run per building every frame if they affect visual state.
- **Current correct pattern**: a single global ticker (`InteriorManager.LateUpdate` every 0.25 s) iterates all registered buildings. This replaced the old `InteriorLightController.Update()` that caused N× dispatches per frame.
- **InteriorLightController.cs is dead/unused** (kept as reference only). New per-building features must follow the global-ticker pattern.

### 3. Interior Generation Is Lazy, Distance-Gated
- Shells (`BuildShellOnly`) are built eagerly at placement (cheap).
- Interiors (furniture, materials) are built ONLY when the player is within `LAZY_RADIUS = 30 m` (`BuildInteriorNow`). **The distance check is REQUIRED**: without it, every registered building builds its full interior immediately → returns the original startup lag.
- This is client-side visual enhancement only; the server does not build interiors.

### 4. Lights Are Always On (no toggling)
- The interior point light attached via `AttachLight` is turned **always on** by the ticker. Distance-based toggling caused sudden street brightness changes (user-visible bug) and is **prohibited**.
- `SetLight(true)` maintains the state; never toggle on/off by distance.

### 5. No Server-Side Build Merge at Runtime
- Building merging during gameplay is **forbidden**: the server synchronizes player state only, never city geometry. 10k concurrent players must not trigger server-side merge work.
- Merge (if ever) must be **offline/baked** in the build pipeline or preprocessing, deterministic, and never a runtime per-connection computation.
- The current in-editor/device merge (`BuildingMergeHelper`) is disabled and must stay disabled (too slow, O(n²)).

### 6. Style Toggle Constraint
- `CityStyle.UseQuaternius` (PlayerPrefs `huntix.citystyle.quaternius`) affects **non-enterable** building visuals only.
- In multiplayer, layout/positions remain deterministic (GeoBlockSeed); aesthetics may differ between clients if the toggle differs. Do not rely on this for gameplay data.
- Decision (user): keep Quaternius; there is no need to remove Kenney, but Kenney must stay a fallback only.

### 7. Building Height
- Shell height is clamped to `[2.8, 4.2] m` in `BuildShellOnly` (single floor). Changing this affects ALL clients and the visual scale; it does NOT affect performance. Do not change without explicit user request.

### 8. New Component/Feature Checklist
When adding anything:
1. Does it run per-building each frame? → Refactor to a global ticker / event.
2. Is the result deterministic given same inputs? → If not, tie to GeoBlockSeed or server-enforced setting.
3. Does it affect other players' view? → Ensure deterministic client-side or server-replicated.
4. Does it risk performance (Update per frame, sync interiors, server merge)? → Reject or offline-bake.

## Violations To Avoid
- Adding `Update()` in a per-building script that mutates renderers/lights.
- Building full interiors for all registered buildings (must stay distance-gated).
- Distance-toggling interior lights.
- Runtime server-side geometric merge for concurrent players.
- Non-deterministic prefab/height choice (Random/Time/session state).

## Reference Fixes Applied (context)
- `GeoBlockSeed` in `BuildingPlacer.cs` (absolute lat/lon style seed).
- Static furniture/material cache in `InteriorGenerator.cs`.
- Static Quaternius prefab cache in `BuildingPlacer.LoadQuaternius`.
- Lazy interiors: `BuildShellOnly` + `PrepareLazy` + `BuildInteriorNow` (distance-gated via `InteriorManager` ticker).
- Global light ticker (always-on) replacing `InteriorLightController.Update()`.

---
*Questa specifica va letta prima di apportare qualsiasi modifica al codice che coinvolga la generazione di edifici, le luci, gli interni, lo stile della città o la performance di caricamento. Ogni nuova funzionalità deve rispettare i vincoli di determinismo multiplayer descritti sopra.*
